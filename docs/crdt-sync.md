# 自動保存・同期

## ライブラリの比較

| 候補 | 特徴 | このアプリでの判断 |
| --- | --- | --- |
| [Yjs](https://docs.yjs.dev/api/document-updates) | Y.Textによる文字列編集。更新は順序に依存せず、重複適用も可能。通信方式を選べる | 採用。textarea、HTTP、既存の認証・SQLiteを利用できる |
| [Automerge](https://automerge.org/docs/tutorial/network-sync/) | 文書の履歴と同期プロトコル、Repoによる保存・通信アダプター | 有力な候補だが、今回は既存のPythonバックエンドにYjs互換のpycrdtを組み込む構成を選択 |

フロントエンドはYjsとy-indexeddb、バックエンドは[pycrdt](https://y-crdt.github.io/pycrdt/api_reference/)を使用する。公開同期サーバーや外部SaaSに日記を送信しない。

## 動作

- 日記の日付ごと、およびテンプレートごとに独立したY.Textを持つ。変更箇所の削除・挿入を行い、全文を置換しない。
- 入力後400msで送信し、2秒間隔とフォーカス復帰・オンライン復帰時にも双方向同期する。日本語IME変換中はサーバー更新の適用を保留する。
- POST `/nikki/{date}/sync` または `/template/sync` でYjs v1形式のバイナリー状態を交換する。単一画面では同時リクエストを1件に限定し、送信中に追加された編集は次の送信に含める。
- IndexedDBに更新を保存する。通信失敗後も編集を維持し、自動再試行する。画面を離れる際にも最終送信を試みる。未送信のまま離れた日付の変更は、その日付を再表示した際に再送する。
- ブラウザーを再起動した場合、キャッシュを開く前にオンラインでユーザーを確認する。完全にオフラインの状態でのアプリ起動には対応していない。ブラウザーのサイトデータを削除すると未送信の変更も削除される。
- `/sync-identity` で確認したユーザーIDとバックエンドURLでキャッシュを分離する。同期APIは認証Cookieと `X-Sync-User` の一致を確認し、別タブでログイン先が変わった場合の誤送信を拒否する。
- SQLiteの `BEGIN IMMEDIATE` で、最新状態の読み込み・マージ・CRDT状態と本文の保存を直列化する。複数ワーカープロセスでも同じSQLiteファイルを使用する必要がある。
- 全文削除後もCRDT履歴を保存する。古い端末が再接続しても、削除済み本文が復活しない。
- ZIP取り込みによる置換と日次テンプレート追加も、同じCRDT状態を更新する。

画面には「同期済み」「未同期の変更があります」、失敗時の再試行状態を表示する。「同期済み」はサーバーが送信済み変更を永続化した状態であり、別の端末にも表示されたことまで保証する表示ではない。

同じ箇所を同時に書き換えた場合、双方の文字列が並ぶなどCRDTのマージ結果になる場合がある。文章としての意味や編集者の意図を自動判定する仕組みではない。

## 導入

1. 既存のSQLiteデータベースをバックアップする。
2. バックエンドで `pip install -r requirements.txt` を実行し、新しいコードで再起動する。
3. フロントエンドで `npm ci` と `npm run build` を実行し、成果物を配置する。
4. 各端末の画面を再読み込みする。

起動時に追加テーブル `collaborativedocument` を作成する。既存の日記・テンプレートは最初の同期時に、サーバー側で一度だけCRDT化する。従来の本文カラムとGET APIは引き続き利用できる。旧PUT APIは409を返すため、バックエンドとフロントエンドを一緒に更新する。移行前から開いている画面の未保存テキストは、再読み込み前に控えておく。

現在は構成の単純さを優先して毎回CRDTの全状態を交換している。リクエスト上限は8MiB。長大な編集履歴では通信量が増えるため、その場合はstate vectorによる差分交換やWebSocketへの拡張を検討する。CRDTテーブルだけを削除・再生成すると既存端末の履歴と整合しなくなるため、本文とCRDT状態は一緒にバックアップ・復元する。

## 検証

- `cd frontend && npm test`：古い端末の編集、IndexedDB復元・再送、日本語IME、遅延応答と日付切り替え。
- `cd frontend && npm run build`：TypeScriptと本番ビルド。
- `cd backend && python -m unittest test_main test_sync`：既存データ移行、同時更新、重複送信、削除、Unicode、ZIP・テンプレート、認証分離、実際のYjsとpycrdtの相互変換。テスト用 `NIKKI_BOOK_SECRET_KEY` を設定して実行する。Node.jsとフロントエンドの依存関係も必要。

バックエンドのテストは一時SQLiteファイルを使用し、実際の日記データにはアクセスしない。
